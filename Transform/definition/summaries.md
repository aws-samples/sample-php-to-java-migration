* "scripts/discover-models.php": The actual model/entity discovery scanner (a copy of `php-model-discovery/scripts/discover-models.php`, placed at this top-level path because ATX's `download_script` tool requires bundled scripts to live directly under `scripts/`, not an arbitrary nested path) — a dependency-free PHP 8.0+ CLI (core `token_get_all`/SimpleXML only, no Composer install, no autoloading, never executes target-app code). Run this against the target application's source root; it finds Eloquent models by walking the class inheritance chain to a configured base class, Doctrine entities by the `#[ORM\Entity]` attribute, and Doctrine XML-mapped entities by parsing `*.orm.xml` files — all three strategies run unconditionally on every scan. Outputs a JSON manifest of every model/entity's fields, casts, relationships, and a `flags[]` array citing anything it could not resolve mechanically (a dynamic property value, an unresolved relationship target, an accessor/mutator containing logic, a magic method, an interface-targeted Doctrine relationship). Usage: `php discover-models.php --root=<path> --pretty --out=manifest.json`.
* "php-model-discovery/SKILL.md": Explains why the scanner discovers by inheritance/attribute/XML-mapping rather than folder convention (folder layout varies per app; inheritance chains and ORM mapping mechanisms don't), documents all three discovery strategies, lists what gets flagged instead of guessed, and records what real open-source apps this scanner has been validated against (a large Laravel app, a small Symfony/Doctrine-attribute app, and a large Symfony/Doctrine-XML-mapping monorepo) including the real bugs found and fixed at each stage.
* "php-model-discovery/references/manifest-schema.md": The full JSON shape of the scanner's output — field-by-field for Eloquent model entries, Doctrine-attribute entity entries, and Doctrine-XML-mapped entity entries, including what a `null`/default value actually means for each field (e.g. `nullable: false` by default reflects Doctrine's own Column default, not the PHP property's nullable type hint) and how to consume `models[]` for JPA entity generation.
* "php-model-discovery/references/config-schema.md": Optional per-app override config (`model-discovery.config.json`) for custom base classes, excluded paths, and cast-type-to-Java-type overrides — most apps need none of this; only write one when an app's conventions genuinely diverge from the scanner's defaults.
* "php-to-java-migration/SKILL.md": The full 8-phase migration methodology this transformation definition is condensed from — assess/discover, build the parity judge, rulebook + gap inventory, stress-test the rulebook, scaffold, translate the data model, translate the I/O layer, convert business logic via an implement/review/fix loop, then compile/run/prove-parity/cutover. Contains the core principles (the PHP code is the spec, fix the loop not the code, verification is mechanical, review is adversarial), the Source Framework Detection table (Laravel/Symfony/CodeIgniter/plain PHP), the PHP-construct gap-inventory table (magic methods, `$$var`, `eval`, `mixed`, duck typing, Doctrine interface-targeted relationships), and the Complex Workflow Mappings table (queues, scheduled tasks, events, caching, file storage, email, WebSocket, PDF generation, search, rate limiting, sessions, background workers, webhooks, external auth providers, fine-grained permissions/ACL, soft-delete-via-dedicated-entity, Gedmo Doctrine extensions). Read this for the full rationale behind any step in `transformation_definition.md`.
* "php-to-java-migration/references/laravel-to-spring.md": Eloquent, queues, events, Blade, Artisan → Spring Boot equivalents, for Laravel-sourced applications.
* "php-to-java-migration/references/symfony-to-spring.md": Symfony bundles, the DI container, Twig, Console → Spring Boot equivalents, for Symfony-sourced applications.
* "php-to-java-migration/references/semantic-traps.md": The full catalog (with PHP/Java code pairs) of PHP behaviors that silently differ in Java: loose `==` comparison, `empty()`, integer division/overflow, negative `substr` offsets, `foreach` by reference, `usort` stability, `strtotime` leniency, string/number juggling, and PCRE vs `java.util.regex` differences. Check every business-logic file being translated against this table.
* "php-to-java-migration/references/composer-to-maven.md": Extended Composer-package-to-Maven-dependency mapping table, beyond the seed table in `SKILL.md`.
* "php-to-java-migration/references/loop-architecture.md": The queue script, adversarial-review, and build-daemon patterns for the business-logic-conversion and compile/prove-parity phases — how to fan work out across many files/agents without hand-patching individual files against a rule.
* "php-to-java-migration/references/app-spec-template.md": A per-application migration spec template (identity, framework/version, codebase inventory, model inventory, gap inventory, workflow mappings, rulebook deltas, parity-harness plan, phase tracker, and a "skill feedback log" for recording any pattern an application surfaces that this transformation definition doesn't yet cover). Use one instance of this per target application when migrating more than one app.
